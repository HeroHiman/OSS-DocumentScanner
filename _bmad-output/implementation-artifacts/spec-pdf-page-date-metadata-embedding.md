## Intent

**Problem:** When a user sets dates on document pages and exports them to a PDF, deleting the document and later re-importing the PDF causes all pages to be treated as brand-new scans with the re-import timestamp. The user has to manually re-enter dates for every page.

**Approach:** Embed page date metadata and extra properties into the PDF's internal metadata dictionary during export, and extract and restore those page dates automatically when re-importing any PDF generated by the app.

## Boundaries & Constraints

**Always:**
- Keep exported PDFs 100% compliant with standard PDF specifications (viewable in Adobe Acrobat, Chrome, Android PDF Viewer, etc.).
- Maintain backwards compatibility: external PDFs without metadata must continue importing normally without errors.
- Preserve all existing date fields (`page.extra.date`, `page.extra.dateTimestamp`, `page.extra.extractedDate`, and `createdDate`).

**Ask First:**
- N/A

**Never:**
- Never modify or corrupt visual page rasterization or OCR text layers.
- Never crash on malformed or third-party PDF metadata.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Export with Page Dates | Pages with `extra.date` and `createdDate` exported to PDF | PDF contains `OSSDocScannerPages` in DocumentInfo with JSON of page metadata | Graceful fallback if extra is undefined |
| Re-import App-Generated PDF | PDF with `OSSDocScannerPages` metadata imported | Pages created with their original `extra.date`, `extra.dateTimestamp`, and `createdDate` restored | N/A |
| Re-import Third-Party PDF | Standard PDF without app metadata imported | Pages created with default import timestamp as before | Silently ignore missing metadata |
| Re-import Corrupted Metadata | PDF with malformed `OSSDocScannerPages` metadata | Pages import successfully as standard pages | Catch JSON parse error and fallback |
